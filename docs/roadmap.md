# 팀 개발 순서

아래 순서로 기능을 개발합니다. 작업은 GitHub Issue로 나누고, API 형식은 관련 담당자끼리 먼저 맞춥니다.

## 1. 공개 저장소 Issue 수집 — 신은지

`backend/app/collection/`, `integrations/`, `api/`에서 저장소 URL 검증, PR 제외, GitHub 페이지네이션, 호출 제한과 부분 수집 표시를 구현합니다. 수집 시각·범위를 보관하고 네트워크 실패가 기존 스냅샷을 손상시키지 않는지 테스트합니다. 분석 작업 상태 API를 검색 담당과 맞춥니다.

## 2. SQLite 저장·검색 — 김민재

`storage/`, `search/`에서 저장 형식과 스냅샷 버전을 정한 뒤 BM25를 먼저 연결합니다. Semantic 모델 의존성은 별도 설치 파일로 분리하고 모델 버전과 캐시 식별자를 기록합니다. 같은 스냅샷에 BM25·Semantic·Hybrid를 적용하고 관련성 판정을 비교합니다.

## 3. Issue 상세·근거 기반 요약 — 김민수 + 신은지

선택한 Issue의 본문·댓글 수집 형식을 정하고, `summarization/`에서 문제상황·발생조건·해결방법·논의결과·후속확인·미확인 사항을 원문 근거와 연결합니다. Ollama 모델을 선정하고 한국어 출력과 응답 형식을 확인합니다. 근거 부족, 부분 수집, 모델 오류에 대한 처리도 추가합니다.

## 4. 검색·상세 대시보드 — 김서현

`frontend/src/features/search/`, `features/issue-detail/`에서 입력, 분석 상태, 검색 결과, 상세 요약과 원문 링크를 구현합니다. API 형식을 정한 뒤 타입을 추가하고 테스트 데이터로 화면을 확인합니다.

## 5. 통합·평가·문서 — 전원

두 공개 저장소에서 시연하고 검색 방식별 관련성, 요약 근거 일치·조건 누락을 점검합니다. API와 예외 테스트, 프런트 빌드를 통과시킨 후 설치·사용법과 한계, 라이선스 고지, 변경 기록을 정리하고 릴리스를 준비합니다.

진행 중에는 '구현 완료'와 '검증 완료'를 별도로 기록합니다. 입력 보조나 수정 PR 확인은 핵심 검색·요약 통합 이후 여유가 있을 때 추가합니다.
